# Code of Conduct

## Our commitment

SSHFlow is built by and for developers, DevOps engineers, system
administrators and security professionals. We want this to be a welcoming
project to contribute to regardless of experience level, background, or
identity.

## Expected behavior

- Be respectful in issues, pull requests, and any other project space.
- Give constructive, specific feedback on code and ideas — critique the
  work, not the person.
- Assume good faith. Most disagreements in a technical project come from
  different context, not bad intent.
- Respect maintainers' time: search existing issues before opening a new
  one, and keep bug reports reproducible and to the point.

## Unacceptable behavior

- Harassment, insults, or personal attacks directed at any participant.
- Discriminatory jokes, language, or imagery.
- Publishing others' private information without consent.
- Sustained disruption of discussions, issues, or pull requests.
- Submitting intentionally malicious code (including anything that would
  weaken the security properties described in [SECURITY.md](SECURITY.md)).

## Enforcement

Project maintainers are responsible for clarifying and enforcing these
standards, and may remove, edit, or reject comments, commits, code, issues
and other contributions that violate this Code of Conduct, or temporarily
or permanently ban any contributor for behavior they deem inappropriate,
threatening, offensive, or harmful.

## Reporting

If you experience or witness unacceptable behavior, please open a GitHub
issue addressed to the maintainers, or, if the report itself is sensitive,
say so in the issue and a maintainer will follow up privately.

## Scope

This Code of Conduct applies within all project spaces (issues, pull
requests, discussions) and in public spaces when an individual is
representing the project.
